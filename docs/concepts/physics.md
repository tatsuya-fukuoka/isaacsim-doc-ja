# 物理シミュレーション

!!! info "対応する公式ドキュメント"
    [Isaac Sim — Physics](https://docs.isaacsim.omniverse.nvidia.com/latest/physics/index.html)

Isaac Sim の物理は NVIDIA **PhysX** エンジンが担い、USD 上では **UsdPhysics / PhysxSchema** というスキーマ(属性の集合)としてシーンに記述されます。

## 物理シーン (Physics Scene)

ステージには通常 1 つの **Physics Scene** プリムを置き、重力・ソルバー設定・GPU シミュレーションの有効化などを設定します。

- 重力: 標準では -Z 方向に 9.81 m/s²
- **タイムステップ**: 物理更新は固定ステップ(例: 60 Hz や 240 Hz)で実行。レンダリングのフレームレートとは独立
- **GPU シミュレーション**: 大量の剛体や強化学習用途では GPU パイプラインを有効化

## 剛体 (Rigid Body) とコライダー (Collider)

メッシュはそのままでは物理に参加しません。役割ごとに API を適用します。

| 適用するもの | 効果 |
| --- | --- |
| **Rigid Body API** | 質量を持ち、重力・衝突で動く剛体になる |
| **Collision API(コライダー)** | 衝突判定の形状を持つ(静的な壁・床はこれだけでよい) |
| 両方 | 「動く+ぶつかる」通常の物体 |

コライダーの近似方法(Approximation)は精度と速度のトレードオフです:

- `convexHull`(凸包)— 標準的。凹形状は再現できない
- `convexDecomposition`(凸分解)— 凹形状もある程度再現。計算コスト増
- `triangleMesh` — 静的オブジェクト向けの正確な形状
- `boundingCube` / `boundingSphere` — 最も高速で粗い

## 関節 (Joint) とアーティキュレーション (Articulation)

ロボットのように多数のリンクが関節で連結された構造は、**Articulation** として扱います。個別の剛体+ジョイント拘束よりも安定かつ高速に解けるのが特徴です。

- **Articulation Root**: ロボットのルートに適用し、リンク群を 1 つの関節系として解く宣言
- 主なジョイント種別: Revolute(回転)、Prismatic(直動)、Fixed(固定)、Spherical(球面)、D6(自由度を個別設定)

### ジョイントドライブ (Drive)

関節を目標値へ動かすには **Drive** を設定します。制御は概念的には PD 制御で:

- **Stiffness(剛性)** — 位置誤差に対するゲイン(P ゲイン相当)
- **Damping(減衰)** — 速度誤差に対するゲイン(D ゲイン相当)

位置制御では Stiffness を大きく、速度制御では Stiffness = 0 にして Damping を使う、という使い分けが基本です。

## 接触・摩擦・マテリアル

**Physics Material** を作成してコライダーに割り当てると、静止摩擦係数・動摩擦係数・反発係数を制御できます。把持シミュレーションでは指先の摩擦設定が結果を大きく左右します。

## 安定性のためのポイント

!!! tip "シミュレーションが暴れるときのチェックリスト"
    - 物理タイムステップを小さくする(60 Hz → 120/240 Hz)
    - ソルバーイテレーション回数(position / velocity)を増やす
    - 質量・慣性が極端(超軽量・超重量の混在)になっていないか確認する
    - コライダー同士がめり込んだ状態で開始していないか確認する
    - ジョイントドライブの Stiffness / Damping が過大でないか確認する

## デバッグ表示

物理挙動の確認には、ビューポートの表示オプションからコライダー形状・接触点・ジョイントの可視化を有効にできます。「見た目のメッシュ」と「物理のコライダー」がずれている問題を発見するのに有効です。
